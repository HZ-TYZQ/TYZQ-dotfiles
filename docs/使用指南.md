# CachyOS 配置使用指南

## 管理范围和分支

本机配置由 `~/.local/share/chezmoi` 的默认分支 `cachyos` 管理，远程仓库为
`https://github.com/HZ-TYZQ/TYZQ-dotfiles.git`。
`fedora` 由原 `master` 重命名而来，保留现有历史，包括已合并的 CachyOS 配置；
旧 Fedora 配置可在迁移前的 Git 历史中查看。
`cachyos` 暂不部署 Yazi、Waybar、Swayidle、Swaylock、
旧 Fedora 自动启动项、终端环境变量、RPM 函数和门户配置；之后需要时再逐项恢复并加入。
这些文件只从当前分支的管理源移除，不删除家目录里的文件。
恢复 Yazi 时，从 `fedora` 分支一并带回 `.chezmoiignore` 中的 Yazi 规则：Noctalia 生成的
flavor 和由 `package.toml` 固定版本的第三方插件不纳管，否则源目录与家目录会反复分歧。

## 仓库结构

仓库根目录的 `.chezmoiroot` 内容为 `home`，chezmoi 只把 `home/` 当作源状态：

- `home/`：对应家目录的源文件，以及 `.chezmoi.toml.tmpl`、`.chezmoiignore`。
- `docs/`、`scripts/`、`README.md`、`.gitignore`、`.gitattributes`：仓库自身的文档和维护文件，不部署。

`chezmoi source-path` 返回 `~/.local/share/chezmoi/home`；`chezmoi git` 仍在仓库根目录执行。
Git 中的源文件路径都带 `home/` 前缀。

## 保存当前配置

```sh
# 更新已经管理的普通文件；模板会被跳过。
chezmoi re-add
# 保存 Noctalia GUI 偏好，同时去除天气坐标。
python3 ~/.local/share/chezmoi/scripts/capture-noctalia.py
# 检查下次 apply 是否会改变家目录。
chezmoi diff
# 检查源仓库相对于上次提交的变化。
chezmoi git status --short
chezmoi git diff
```

新增配置时使用具体路径，例如：

```sh
chezmoi add --secrets=error ~/.config/nvim/lua/plugins/new-plugin.lua
```

审查源文件后，用明确路径暂存。例如：

```sh
cd ~/.local/share/chezmoi
git add home/dot_config/kitty/kitty.conf
git diff --cached
git diff --cached --check
git commit -m "Update Kitty preferences"
# 需要同步到 GitHub 时执行；首次推送也会建立上游分支。
git push -u origin cachyos
```

仓库为公开仓库。不要提交登录凭证、密钥、访问令牌、浏览器档案、输入法学习数据或私密文本。
`.chezmoiignore` 控制 chezmoi 管理哪些目标路径；Git 是否忽略源文件由 `.gitignore` 控制，
已经被 Git 跟踪的文件还需要停止跟踪。两者都不是完整的敏感信息检查器。
`private_` 只控制文件权限，并不加密内容或阻止 Git 提交。不要用 `git add .` 或 `git add -A` 代替审查。

## 会话环境变量

`~/.config/environment.d/` 是会话环境变量的唯一来源：

| 文件 | 变量 |
| --- | --- |
| `50-editor.conf` | `EDITOR`、`VISUAL` |
| `60-qt.conf` | `QT_QPA_PLATFORMTHEME` |
| `70-npm.conf` | `NPM_CONFIG_USERCONFIG` |

systemd 用户管理器读取这些文件，Niri 作为 `niri.service` 启动并继承它们，再传给
快捷键、启动器和终端打开的程序。Niri 的 `conf.d/session.kdl` 只保留会话专用的 `XMODIFIERS`。

TTY 和 SSH 登录不经过用户管理器，所以 Fish 的 `conf.d/00-environment.fish` 和 `~/.zshrc`
会调用 systemd 的 `30-systemd-environment-d-generator` 导入同一份变量。已经设置的值优先，
不会覆盖图形会话的环境或临时指定的值。

新增变量只需在 `environment.d` 中加一个文件，不要再在 Shell 配置里重复设置。
新终端会立即带上新增的变量；修改已有变量的值需要重新登录图形会话才对所有程序生效。

## Git 和 npm

Git 全局配置的源文件为 `home/dot_config/git/config.tmpl`，公开部分只有 gh 凭据助手设置。
提交身份来自本机 `~/.config/chezmoi/chezmoi.toml` 的 `[data]`：

```toml
[data]
    gitName = "..."
    gitEmail = "..."
```

新机器执行 `chezmoi init` 时会提示输入这两项，之后重新初始化会保留已有值。
不要用 `chezmoi add` 覆盖模板；`.gitignore` 会拦截渲染后的 `home/dot_config/git/config`，
避免把身份写进公开仓库。gh 登录需要在新机器单独执行 `gh auth login`。

npm 配置位于 `~/.config/npm/npmrc`，保存安装前缀、镜像源和缓存位置，可以公开；
路径用 npm 支持的 `${HOME}` 展开。npm 缓存放在 `~/.cache/npm`，不纳入仓库。
如果以后需要私有 registry 的 Token，写成 `//registry.example/:_authToken=${NPM_TOKEN}`，
Token 本身放在本机环境变量里，不要直接写进 npmrc。

## 应用和拉取

```sh
chezmoi diff
chezmoi apply --dry-run --verbose
chezmoi apply
```

先保存家目录中需要保留的新修改，确认差异后再应用。不要用 `--force` 覆盖冲突。
从远程更新时先只拉取，不自动部署：

```sh
chezmoi update --apply=false
chezmoi diff
chezmoi apply --dry-run --verbose
chezmoi apply
```

## Niri

入口为 `home/dot_config/niri/config.kdl`，按顺序加载 `conf.d/` 中的片段：

| 片段 | 内容 |
| --- | --- |
| `session.kdl` | 会话环境、启动程序、快捷键提示和截图路径 |
| `input.kdl` | 键盘、触摸板和鼠标 |
| `outputs.kdl` | 显示器（模板，由本机数据生成） |
| `appearance.kdl` | 布局、动画、模糊和光标 |
| `rules.kdl` | 窗口和图层规则 |
| `binds.kdl` | 快捷键 |

`outputs.kdl.tmpl` 是通用模板，屏幕标识、模式和缩放只保存在本机
`~/.config/chezmoi/chezmoi.toml` 的 `[data]` 中：

```toml
[data]
    niriOutputName = ""  # 填入 niri msg outputs 返回的完整厂商、型号和序列号
    niriOutputMode = ""  # 留空使用屏幕首选模式；指定值需与 niri msg outputs 一致
    niriOutputScale = 0  # 0 表示由 Niri 自动选择；也可指定 1.5 等缩放值
```

这些本机参数不写入 Git，也不依赖主机名。`niriOutputName` 未设置或为空时，
模板不生成 `output` 块，由 Niri 自动选择显示模式和缩放，新机器不会继承其他机器的硬件参数。
填写屏幕标识时，复制 `niri msg outputs` 第一行中引号内的完整内容，并保留空格；
不要使用 `eDP-1` 等接口编号，它们可能随驱动初始化顺序变化。
`.chezmoi.toml.tmpl` 会在重新初始化时保留已有的本机参数。
模板将所选屏幕置于原点并保持正常方向；以后需要多屏布局时，再把数据扩展为输出列表。

调整本机参数后，先检查渲染差异，再仅应用显示器片段：

```sh
chezmoi diff ~/.config/niri/conf.d/outputs.kdl
chezmoi apply ~/.config/niri/conf.d/outputs.kdl
niri validate
```

修改模板使用 `chezmoi edit ~/.config/niri/conf.d/outputs.kdl`；不要用 `chezmoi add`
把渲染后的 `outputs.kdl` 覆盖到模板，以免把本机硬件参数写入共享配置。
入口和其余片段是普通文件，可正常 `re-add`。Niri 会在文件变化时自动重载；
同时修改多个文件时，先确认 `niri validate` 通过。

`noctalia.kdl` 由 Noctalia 的 Niri 主题模板生成并最后加载。首次迁移时要先恢复此文件
或让 Noctalia 生成它，再验证 Niri 配置；它不存入 Git。
家目录中旧的 `~/.config/niri/cfg/` 不是当前入口使用的配置。

## Noctalia

基础配置位于 `~/.config/noctalia/config.toml`；GUI 偏好位于
`~/.local/state/noctalia/settings.toml`，后者只在本机 chezmoi 源目录管理。
其源副本 `home/private_dot_local/state/noctalia/` 含个人壁纸和头像文件名，
由 `.gitignore` 排除，需要另行备份并在新机器恢复。
保存 GUI 修改使用 `scripts/capture-noctalia.py`，不要对这个文件直接 `chezmoi add`。
模板应用时保留目标机器当前 `[location]` 表；新机器没有位置时不会带入旧机器坐标，
需要在 GUI 中设置天气位置。无效 TOML 会报错，不会被静默覆盖。

壁纸路径会随家目录变化，图片本身不入库。当前依赖 `~/Pictures/Wallpaper/` 中的图片。
Phonto 仍为禁用状态，保留了它的配置项；这里不会安装或启用插件。
其余状态（剪贴板、插件仓库、缓存、运行时数据）不纳管。
Noctalia 生成的 Niri、GTK、Qt、KDE 调色输出不作为手写配置保存。

## 应用图标

Noctalia 启动器、Dock 与 GTK 3/4 应用使用 Papirus-Dark，依赖 `papirus-icon-theme`。
`~/.config/gtk-3.0/settings.ini` 和 `~/.config/gtk-4.0/settings.ini` 保存图标偏好；
Niri 的 `conf.d/session.kdl` 在登录时设置 GSettings 的桌面图标主题。
当前会话立即应用可运行：

```sh
gsettings set org.gnome.desktop.interface icon-theme Papirus-Dark
```

Noctalia 会检测系统图标主题变化并刷新。GTK 的 `gtk.css` 继续由 Noctalia 生成，不入库。
若以后更换图标主题，同步调整以上设置与 Qt6ct 的 `icon_theme`。

## Qt6ct

`~/.config/qt6ct/qt6ct.conf` 管理 Fusion 风格、Noto Sans / Noto Sans Mono 10 pt
和 Papirus-Dark 图标。运行依赖为 Qt6ct、Papirus 图标主题和 Noto 字体。
配色路径由 `home/dot_config/qt6ct/qt6ct.conf.tmpl` 使用 `{{ .chezmoi.homeDir }}` 渲染为
`~/.config/qt6ct/colors/noctalia.conf`，随用户名自动变化。配色文件由 Noctalia 的 `qt`
内置模板持续生成，生成的 `colors/` 目录不入库。

`~/.config/environment.d/60-qt.conf` 设置 `QT_QPA_PLATFORMTHEME=qt6ct`；
用户服务和 Niri 启动的应用都从这里继承，见「会话环境变量」。
首次应用后，可运行 `dbus-update-activation-environment --systemd QT_QPA_PLATFORMTHEME=qt6ct`
更新当前用户服务与 D-Bus 的启动环境。重新打开终端和 Qt 应用后使用新设置。

用 `chezmoi edit ~/.config/qt6ct/qt6ct.conf` 编辑源模板。通过 Qt6ct 界面调整偏好后，
把对应选项同步到模板，保留家目录占位符；普通 `chezmoi re-add` 会跳过模板。
Noctalia 配色文件由它自动维护。

## mpv

`~/.config/mpv/` 管理播放配置、快捷键、Mochi 控制栏及 `powermode.lua`。
依赖 `mpv`、Noto Sans CJK SC 和 Material Symbols Rounded；网络视频链接解析另需 `yt-dlp`。
图标字体已从备份恢复到 `~/.local/share/fonts/MaterialSymbolsRounded.ttf`，字体文件本身不入库。

当前使用 gpu-next、Vulkan 和自动硬件解码，已在本机 RTX 5060 上试播验证。
电池供电时脚本降低渲染开销；`Ctrl+b` 循环切换自动、省电和性能模式。
`DEL` 切换控制栏显示方式，`[` / `]` 调整倍速，截图保存到 `~/Pictures/mpv/`。
换机器时按显卡支持调整 `gpu-api`；主配置里的机器说明仅描述当前笔记本。
Mochi 配色保留备份中的暖棕色设置，可在 `script-opts/mochi.conf` 修改。

只纳管这六个配置和脚本文件；播放历史、续播进度、缓存和截图留在本机。

## Fcitx5、终端和编辑器

只管理 `~/.config/fcitx5/` 中明确选择的配置文件，以及当前浅色/深色主题。
主题源副本位于 `home/private_dot_local/private_share/private_fcitx5/themes/`。
两套主题都是第三方作品，`bed-money` 的素材声明还限制了用途，因此由 `.gitignore` 排除，
不在公开仓库再分发；它们只在本机保留，新机器需另行恢复。
`cached_layouts`、拼音用户词库和主题备份留在本机。
`bed-money` 的原作者与素材限制声明随主题保留。

Fish 使用 CachyOS 提供的 `/usr/share/cachyos-fish-config/cachyos-config.fish`，
叠加自己的 Fastfetch、Starship 和欢迎语；默认编辑器等环境变量来自 `environment.d`。
此分支面向 CachyOS。
Kitty 为首选终端，Alacritty 为备用；字体依赖 `CaskaydiaCove Nerd Font Mono`，
输入法字体依赖「荆南麦圆体」。字体文件、鼠标指针、壁纸另外备份。

Neovim 管理配置和 `lazy-lock.json`，不管理下载的插件、Mason 工具、会话、撤销历史和缓存。
插件可根据锁定文件重新下载；语言工具和调试器由 Mason 管理。迁移到新机器后需要重新安装
这些运行依赖，不应把旧 Python 虚拟环境直接当作配置纳入 Git。

## 在新机器初始化

将 `cachyos` 分支推送到 GitHub 后：

```sh
chezmoi init --branch cachyos https://github.com/HZ-TYZQ/TYZQ-dotfiles.git
chezmoi diff
chezmoi apply --dry-run --verbose
# 检查软件、字体、壁纸、显示器参数后再应用。
chezmoi apply
```

初始化时会提示输入 Git 的 `user.name` 和 `user.email`；显示器参数默认留空，
需要时再按「Niri」一节填写。初始化不加 `--apply`，先审查部署内容。有现存配置时先备份。
本仓库不会安装系统软件，也不会修改 `/etc`。

## 排除与退出管理

不要纳管整个 `~/.local/state`、`~/.local/share` 或 `~/.config`。
需要停止管理某个文件时，`chezmoi forget 路径` 只移除源状态，保留家目录文件。
没有自动提交或推送；家目录的修改通过上述保存步骤进入 Git 历史。

模板使用 chezmoi 官方的 [include](https://www.chezmoi.io/reference/templates/functions/include/)
和 [stat](https://www.chezmoi.io/reference/templates/functions/stat/) 读取本机位置设置；
排除规则见 [.chezmoiignore 文档](https://www.chezmoi.io/reference/special-files/chezmoiignore/)。
